# Testing & Compatibility Strategy

## 1. Quality Assurance Vision

Emulation software requires rigorous testing across multiple domain layers: pure Dart logic, local SQLite persistence, platform channels, native C++ JNI core execution, and physical gamepad/touch input rendering.

This strategy establishes a multi-tier testing framework ensuring both functional correctness and backward compatibility for existing Lemuroid users.

```
       / \
      /   \     Integration Tests (Real Android Devices / Emulators)
     /  I  \    - Full ROM launch, JNI lifecycle, Android TV D-pad focus
    /-------\
   /    W    \   Widget & UI Tests (Flutter Test Framework)
  /-----------\  - Screen layouts, Touch overlays, Settings tiles, Dialogs
 /      U      \  Pure Unit Tests (Dart + Mocktail)
/---------------\ - Libretro DB parser, Cheat parser, Serial scanner, Drift DB
```

---

## 2. Multi-Tier Testing Pyramid

### 2.1 Pure Dart Unit Tests (`test/features/...`)
- **Scope**: Isolated business logic, parsing algorithms, database DAOs, and state notifiers without native Android dependencies.
- **Tools**: `test`, `mocktail`, `drift_dev/test`.
- **Target Coverage**: **> 85%** for domain models, parsers, and repositories.
- **Key Unit Test Suites**:
  1. `libretro_db_parser_test.dart`: Validates binary `.rdb` header extraction and game metadata queries.
  2. `cw_cheat_parser_test.dart`: Verifies CwCheat string parsing into valid Libretro address/value pairs.
  3. `serial_scanner_test.dart`: Tests binary header serial extraction across PSX, GBA, N64, and PSP mock byte buffers.
  4. `drift_database_test.dart`: Executes in-memory SQLite CRUD queries on `games`, `data_files`, and `game_cheats` tables.

### 2.2 Flutter Widget & Screen Tests (`test/widgets/...`)
- **Scope**: UI component layout rendering, user interaction handling, theme styling, and state changes.
- **Tools**: `flutter_test`, `riverpod` container overrides.
- **Key Widget Test Suites**:
  1. `library_home_screen_test.dart`: Verifies game grid rendering, empty state display, and search filter input.
  2. `touch_controller_overlay_test.dart`: Verifies touch drag gestures and multi-button press event firing.
  3. `save_slot_picker_test.dart`: Verifies save state slot selection, preview image loading, and overwrite confirmation dialogs.

### 2.3 Platform Channel Mock Testing
- **Scope**: Validating Dart `NativeEmulationBridge` error handling and command formatting when communicating with native Android code.
- **Implementation**:
  ```dart
  void setupMockEmulationChannel() {
    TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger
        .setMockMethodCallHandler(
      const MethodChannel('com.swordfish.lemuroid/emulation_command'),
      (MethodCall methodCall) async {
        if (methodCall.method == 'initializeCoreAndGame') {
          return true; // Simulate successful JNI initialization
        }
        if (methodCall.method == 'saveState') {
          return '/storage/emulated/0/Lemuroid/states/snes/game.state1';
        }
        throw PlatformException(code: 'UNSUPPORTED_METHOD');
      },
    );
  }
  ```

### 2.4 Native Integration Tests (`integration_test/`)
- **Scope**: End-to-end execution on real Android hardware or AVD emulators.
- **Tools**: Flutter `integration_test` package, Android ADB runner.
- **Execution Workflow**:
  1. Boot app in test mode with sample homebrew ROMs.
  2. Trigger `startSession(game)`.
  3. Assert `GLRetroView` surface creation.
  4. Send synthetic key event (D-pad START button) via Android ADB.
  5. Save state to Slot 1, restart emulation session, and restore state from Slot 1.
  6. Assert game RAM state restoration.

## 3. Backward Compatibility & Data Migration Strategy

To guarantee zero loss for upgrading users, the migration includes three explicit compatibility verification steps:

### 3.1 Database Migration Verification (`retrograde.db`)
- **Test Objective**: Verify that opening an existing Room database created by Lemuroid Kotlin version 1.17.0 correctly imports all games, cover URLs, favorite statuses, and cheat entries into Drift SQLite without data loss.
- **Validation Script**:
  1. Load seed SQLite database `retrograde_v1.17.0.db` generated by legacy Kotlin app.
  2. Initialize Flutter `AppDatabase` with migration handler.
  3. Query `games` table and assert item count and schema column integrity.

### 3.2 Save File & Save State Cross-Compatibility
- **Test Objective**: Ensure that SRAM save files (`.srm`, `.sav`) and save state binary files (`.state`, `.state0`–`.state9`) created by legacy C++ Libretro cores load identically in the new Flutter application.
- **Validation Script**:
  1. Copy legacy save file `SuperMario.srm` and state file `SuperMario.state1` into target save directory.
  2. Launch game in Flutter app and trigger `loadState(1)`.
  3. Verify that native Libretro JNI returns `true` for `retro_unserialize()`.

## 4. Performance & Frame Timing Benchmarks

Because emulation requires sustained 60 FPS (16.6 ms per frame) output, performance testing is integrated into release acceptance criteria:

| Metric | Target Threshold | Test Method |
| :--- | :--- | :--- |
| **Video Frame Rate** | **60 FPS ± 0.5** (16.6 ms/frame) | Android FrameMetrics API / SurfaceFlinger logs |
| **Input Latency** | **< 12 ms** (Touch / Gamepad to JNI) | High-speed camera capture / Logcat timestamp delta |
| **Library Indexing Speed** | **> 100 ROMs / second** | Dart Stopwatch timing during SAF directory traversal |
| **Memory Footprint** | **< 150 MB** (excluding core RAM allocation) | Android Studio Profiler heap memory analysis |
| **Startup Time (Cold Launch)** | **< 1.2 seconds** to Library Home Screen | Flutter Performance Overlay & ADB cold boot trace |

---

## 5. Physical Test Device Matrix

Testing must cover the diverse Android hardware ecosystem on which Lemuroid runs:

1. **Touchscreen Mobile Phone**: Modern Android 12+ device (e.g., Google Pixel / Samsung Galaxy) for touch skin gesture and aspect ratio tests.
2. **Android Tablet**: Large screen tablet (e.g., Galaxy Tab) for dual-column UI and touch control resize testing.
3. **Android TV Streaming Box**: Google TV / Shield TV box with connected Bluetooth gamepad for D-pad focus navigation and Leanback row integration.
4. **Dedicated Handheld Console**: Android gaming handheld (e.g., Ayn Odin / Retroid Pocket) with built-in hardware controller buttons for low-latency physical key mapping verification.
